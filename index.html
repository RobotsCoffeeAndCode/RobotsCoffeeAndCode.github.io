My work includes three enhancements to my IT145, Foundations in Application Development, Project Two submission. I completed this Java project during my first term at Southern New Hampshire University. It is a console application designed for internal use by a rescue animal company to track its inventory. It allows users to view all rescue animals, their training statuses, and whether a third party has reserved them for a rescue. I will express more details about the application in the following section, but essentially it is a bare-bones, local data management application.

My three enhancements demonstrate my ability to build each core function. In addition, I changed the language that I wrote the original software in from Java to C++. I used clang-tidy throughout the development process to ensure security was never an afterthought. Lastly, I used CMake to statically link all libraries used within the application, ensuring that the binary runs on any Windows device after compilation.

Software Engineering & Design

I anticipated that this initial enhancement would be substantial, but I did not expect it to require so much time. This oversight was primarily due to the effort I invested in making the project conform to industry-standard software engineering practices. In retrospect, I made the challenging decision to move beyond the tools I was familiar with, Visual Studio and MSVC (Microsoft’s C compiler), and adopt another compiler widely recognized in the industry: LLVM's Clang. This is not to say that MSVC compiler or Visual Studio is a bad IDE choice, but I wanted to leverage the efficiency optimizations that come with clang for future work.

I made this choice for several key reasons. First, I aspire to become an embedded systems engineer, a role that requires a strong foundation in C and C++. Developing that foundation involves working more closely with the compiler and tools such as Makefiles and CMake. Second, Clang includes a range of built-in tools. For example, I use clang-tidy, a static analysis tool included with Clang, to improve the security of my code. Finally, using Clang with CMake offers flexibility: including a CMake build file in a project allows tools to be added to the build toolchain as needed. For instance, I run a simple Google Test suite as the final step in my build process to verify that my unit tests pass before testing runtime features.

These considerations led me to try Clang and adopt a less structured, yet organizationally demanding project setup. After installing and configuring everything, learning how to compile the project correctly, encountering repeated failures, and reimplementing Google Test, I was able to get a small piece of C++ code working properly.

After writing C++ code using clang-tidy and clangd (Clang's built-in Language Server Protocol, or LSP), I realized that I had significant room for improvement in my C++ programming. For example, I was unaware that a modern style convention is to begin a function definition with the keyword `auto` and specify the return type afterward. I was also unfamiliar with the chrono library, as I rarely have worked with calandar dates. However, as my project made heavy use of them I used the `year_month_day` object frequently. This proved to be extremely useful for tracking rescue animal date data. I also had to become accustomed to clangd’s formatting conventions. Initially, it was difficult to read my function parameters because I usually place each parameter on a separate line, whereas clangd prioritizes an 80-column line width. I eventually learned how to configure it to enforce line-by-line parameters, but by then I was nearly finished with the second enhancement.
